## 원인 (가설 — 실제 API 응답 미검증 상태에서 설계된 결함)

DEF-B-063(`AddressInput.tsx` `onComplete` 콜백)은 Daum 응답의 **`sigunguEnglish`**(영문 변환 필드, 예상 형식 "Seongnam-si Bundang-gu")를 `country-state-city` 라이브러리 옵션과 최장 prefix 매칭한다. 이 설계는 실제 Kakao API가 이 필드를 항상 예상한 형식으로 채워준다는 가정 위에 세워졌는데, **이 가정 자체가 실제 API로 검증된 적이 없다.**

Kakao 우편번호 위젯은 iframe 기반 UI라 서버 사이드에서 직접 응답을 재현할 수 없어(Jaison 환경에 브라우저 없음), 정확한 실패 지점(예: `sigunguEnglish`가 빈 문자열인지, 예상과 다른 순서/형식인지)은 아직 실측되지 않았다. 다만 **`sigunguEnglish`(영문 변환)는 Kakao API 사양상 필수/핵심 필드가 아니라 부가 필드**이므로 일부 도로(특히 대왕판교로처럼 비교적 신설된 도로명)에서 비어있거나 불완전할 가능성이 높다는 것이 JSJung·Jaison 공통 결론.

## 수정 방향 (TASK-B-298에 배정)

(2026-08-13 JSJung 제안) **`sigunguEnglish`(영문, 신뢰 불가) 대신 `sigungu`(한글, Kakao API 핵심/필수 응답값이라 항상 채워짐)를 1차 매칭 소스로 사용**하도록 전환:

1. `data.sigungu`(예: "성남시 분당구")를 공백 기준으로 분리 → 첫 토큰("성남시")을 취한다.
2. 이 한글 시 이름을 라이브러리 문자열로 변환하는 **소규모 고정 매핑 테이블**을 신설(기존 `KR_SIDO_TO_ISOCODE`와 동일 패턴) — **전국에서 구(區)가 설치된 일반시는 아래 12개로 고정돼 있어 과설계 아님**(직접 라이브러리 데이터 대조 확인 완료):
   ```js
   const KR_GU_CITY_TO_LIBNAME: Record<string, string> = {
     '수원시': 'Suwon',        // 주의: 라이브러리에 '-si' 접미사 없음
     '성남시': 'Seongnam-si',
     '안양시': 'Anyang-si',
     '부천시': 'Bucheon-si',
     '안산시': 'Ansan-si',
     '고양시': 'Goyang-si',
     '용인시': 'Yongin-si',
     '청주시': 'Cheongju-si',
     '천안시': 'Cheonan-si',   // 'Cheonan'도 라이브러리에 별개 존재 — 반드시 '-si' 버전 사용
     '전주시': 'Jeonju-si',    // 'Jeonju'도 별개 존재
     '포항시': 'Pohang-si',    // 'Pohang'도 별개 존재
     '창원시': 'Changwon-si',  // 'Changwon'도 별개 존재
   };
   ```
3. `sigungu`의 첫 토큰이 위 매핑에 있으면 **그 값을 그대로 사용**(Kakao 영문 필드 의존 완전 배제, 100% 결정적).
4. 매핑에 없으면(서울 구 단위 등 기존에 이미 정상 동작하던 케이스) **DEF-B-063에서 만든 기존 `sigunguEnglish` 최장 prefix 매칭 로직을 폴백으로 그대로 유지** — 회귀 없음.

과설계 금지 — 전국 모든 시/군/구를 한글로 매핑하는 완전한 테이블 구축은 범위 밖. 구가 있는 12개 시만 하드코딩, 나머지는 기존 폴백 로직 재사용.

## 회귀 테스트 방향
