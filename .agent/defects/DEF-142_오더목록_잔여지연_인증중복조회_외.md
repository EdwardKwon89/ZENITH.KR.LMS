## 원인 (Aiden 코드 교차검증으로 확정)

### ① 인증·프로필 조회 3중복 (가장 확실한 원인, Aiden 코드 확인 완료)

[`orders/page.tsx`](../../src/app/[locale]/(dashboard)/orders/page.tsx)의 `requireAuth()`와 [`getOrders()`](../../src/app/actions/operations/orders.ts) 내부의 `validateUserAction()`([`guards.ts`](../../src/lib/auth/guards.ts))가 **완전히 동일한 `supabase.auth.getUser()` + `zen_profiles` SELECT를 각각 독립적으로 실행**함 — 페이지 1회 전환마다 동일 사용자 정보를 최소 2회(요청 흐름에 따라 B_Kai 관측상 3회) 중복 조회.

**⚠️ 전역 영향 확인**: 이 패턴은 Orders 페이지만의 문제가 아님. `grep` 결과 `validateUserAction()`은 서버 액션 **46개 파일**, `requireAuth()`는 페이지 **41개**에서 사용 중 — 두 헬퍼가 같은 요청 흐름(페이지→서버액션)에서 함께 호출되는 경우 플랫폼 전역에서 동일한 중복조회가 반복되고 있을 가능성이 높음. 이는 Orders 단일 화면 버그가 아니라 **구조적 패턴 문제**.

### ② `SELECT *` (61컬럼) × 20행 + `count=exact`

[`OrderRepository.findList()`](../../src/lib/repositories/order.repository.ts)가 `select('*', ...)`로 전체 컬럼을 가져오는데, `OrderDataTable.tsx` 렌더링에 실제 필요한 컬럼은 일부뿐. 불필요한 payload 크기 증가.

### ③ `OrderFilterBar` 마운트 후 공통코드 조회 2건

클라이언트 마운트 후 `getCommonCodesByGroup`을 2회 호출 — 서버에서 1회로 묶을 수 있는 여지.

### ④ Sentry 터널(/monitoring) 경합

매 페이지뷰마다 Sentry envelope 전송이 발생하며 일부 800ms대 소요 관측(로컬) — production 재확인 필요, 네트워크 경합 가능성.
