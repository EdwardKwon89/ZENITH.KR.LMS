## 1. 목표 상태 (JSJung 확정, 2026-11-27)

1. UPS 인보이스(오더)의 마감은 **신규 정산마감 경로(`finalizeUpsSettlement`, TASK-B-381 구현 기준) 하나뿐**이다. 인보이스 **단건 마감과 실비 등록·청구확정 연계 마감을 포함한 다른 어떤 경로로도 마감되지 않는다**(예외 없음). 기존 UPS 인보이스는 M4(일괄 취소)에서 정리한다.
2. UPS 여부를 판정하지 못하는 경우(조회 제한·실패)는 **fail-closed**이다: 마감되지 않고 `skippedCount` 또는 `failedCount`로 집계된다(`finalizedCount === 0`, DB `is_finalized = false`). 기존 소유권·권한 확인에 의존하지 않고 UPS 가드 자체가 막는다.

## 2. 판정 기준 (해소 조건)

1. **마감 권한이 있는 모든 역할**의 **모든 마감 진입점**(일괄·단건·실비 등록 연계·직접 호출)에서 UPS 인보이스의 `is_finalized`가 `true`가 되지 않음을 실DB 세션 통합 테스트로 **값 단언**한다(`status` 컬럼은 마감 때 바뀌지 않으므로 판정에 쓰지 않는다).
2. 신규 테스트는 UPS 가드를 임시로 비활성한 상태에서 **테스트별로 실패**함을 확인한다.
3. 비UPS 대조군은 기대 결과를 갖는다(허용 케이스가 구체 값으로 양성).
