## 결함 내용

`rejectInvoice`는 인보이스 취소 후 연결된 원가 행의 연결을 해제하지만, 인보이스 발행 후 원가 변경을 막는 트리거(`trg_prevent_cost_change_after_invoice`)가 해당 UPDATE를 차단합니다. 호출부가 반환 오류를 확인하지 않아 **역할과 무관하게 조용히 실패**합니다.

- 실측 완료, 상세 비공개(세션·권한별 결과는 공개 기재하지 않음).
- UPS 인보이스 경로 제거 후에도 **비UPS `rejectInvoice` 경로에 남습니다**(task file §4-3 #3).
- 본 DEF는 **기능 결함**이며, 권한 설계의 목표 상태(정책 0개)와는 무관합니다.

## 영향

- 인보이스를 취소해도 원가 연결이 남아, 재발행 인보이스의 합계·연결 정합성이 어긋날 수 있습니다.
- 오류 로깅·사용자 알림이 없어 **조용한 실패**로 남습니다(ZEN_A4 실패 관측성 원칙 위반).

## 권장 조치

1. 트리거 예외를 피하는 경로를 별도 설계합니다(예: 취소 트랜잭션에서 허용하는 전용 RPC 또는 트리거 조건 추가). **단순 트리거 제거는 인보이스 발행 후 비용 변형 방지 규칙이 깨지므로 금지**.
2. 호출부에서 반환 오류를 확인하고 로깅합니다.
3. 수정 Task 별도 발령(본 Task 범위 밖).

## 범위 밖 선언

본 Task(#1463 / TASK-B-382)는 **설계 의견 전용**이며 코드·정책 변경이 없습니다. 발견 즉시 R-18로 등록하고, 설계 문서에는 영향 범위 표의 판정만 반영합니다.
