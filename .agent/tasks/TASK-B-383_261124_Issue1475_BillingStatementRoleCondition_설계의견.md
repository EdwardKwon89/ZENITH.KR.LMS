### 2. 변경 후 목표 표 (역할 × 발행 조직 — 공개 표는 이 표뿐)

### 3. 정책 변경안 비교 + 권장안 (기존 정책 2개의 조건 수정 — 새 정책 없음)

공통 구조: **헤더 정책·항목 정책 각각의 "발행자 일치" 분기에만** 조건을 더하고, 발행 조직이 플랫폼이 아닌 경우에는 조건이 없도록 합니다(대리점 발행분은 영향 없음). 발행 조직이 플랫폼인 경우에만 **역할이 ADMIN·ZENITH_SUPER_ADMIN인지** 확인합니다. 나머지 분기(수신자·감독)와 쓰기 정책은 **변경하지 않습니다.**

| 안 | 역할 조건의 출처 | 장점 | 단점 |
|:--|:--|:--|:--|
| **안 1 (권장)** | **DB 프로필** (`auth.uid()` 기반 조회) | 같은 정책 파일의 **감독 분기·쓰기 분기가 이미 쓰는 출처와 동일** → 단일 출처, 역할 변경 즉시 반영, 세션 클레임 어긋남(레거시 세션) 영향 없음 | 프로필 조회 서브쿼리 1회 |
| 안 2 | 세션 클레임(인증 메타데이터) | 서브쿼리 불필요, 읽기 경로 가벼움 | 프로필과 세션이 어긋날 수 있는 레거시 세션 존재(인증 프록시의 클레임 fallback 존재 근거) → **이중 출처** |

- **권장: 안 1.** 근거: 정책 축이 역할·조직인데 출처가 둘이 되면 정합 사각지대가 생긴다(이슈 사전 경고의 "테스트가 수정 대상을 검증하지 못함" 유형과 같은 클래스). 안 1은 기존 분기와 출처가 같아 되돌리기·매트릭스 단언도 한 출처로 재현된다.
- 구조 변형안(발행자 분기를 플랫폼/비플랫폼으로 분리)은 **새 정책이 아닌 기존 조식 수정** 안에서만 가능하며 위 두 안과 결과가 같으므로 별도 검토 대상 아님.

### 4. 테스트 계획 (R-09 — 구현 시, 실제 세션 SELECT로 바로 그 정책을 검증)

1. **매트릭스**: 픽스처(플랫폼 발행 1건 + 대리점 발행 1건, 헤더·항목) + **존재하는 역할 전부**(ADMIN·ZENITH_SUPER_ADMIN·MANAGER·SUB_ADMIN·OPERATOR·AGENCY 계열·화주 계열) 실제 로그인 구조 세션으로 헤더·항목 SELECT — 목표 표의 모든 셀을 단언.
2. **양성 대조**: 허용 역할(ADMIN·ZENITH_SUPER_ADMIN, 수신자 자격 대리점·화주)은 **변경 전과 동일한 결과**를 반드시 반환(차단이 넓어지지 않았는지).
3. **되돌리기 실측**: 마이그레이션 롤백 SQL로 정책 원복 → 매트릭스가 **변경 전 상태로 돌아가는 것**(차단 셀이 다시 열리는 것)을 실측, 원문 복원 후 재단언까지. 커밋 금지·로컬만.
4. **afterAll 원복 + 잔여 0건 단언**(헤더·항목·오더·프로필·조직 전부).
5. 소스 문자열(`toContain` 등) 단언 **금지** — 측정은 전부 세션 SELECT 결과값으로.
