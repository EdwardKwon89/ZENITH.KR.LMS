## 4. 금액 동일성 검증 계획 (전환 전/후 대조)

판정 기준: 동일 오더·동일 tier에 대해 7개 반환 컬럼이 **완전 일치**하고, `line_total = round(b)+round(f)+round(s)+round(o)` 불변식이 유지된다 것.

| 역할 | 검증 맥락 | 판정 |
|:--|:--|:--|
| `ADMIN` | 후보조회 + 통합 생성(화주/대리점 tier 양쪽) | 전환 전/후 7컬럼 동일. 대리점 tier에서 `agency.*` 우선값 유지 확인 |
| `AGENCY` | 후보조회 + ADHOC/등록 화주 생성(소속 오더만) | 소속 오더 금액 동일, 타 org 오더는 가드로 거부 |
| `MANAGER` | 스냅샷 갱신 주체(§5). 청구 발행 권한은 없음 | MANAGER가 갱신한 스냅샷을 ADMIN/AGENCY가 조회·청구할 때 금액이 갱신값으로 일관 반영 |
| `ZENITH_SUPER_ADMIN` | 발행자 + 안전 뷰 role 정렬 확인 | `ADMIN`과 동일 금액. 정책 role 집합 정렬(§6-3) 후에도 동일 |

- **실제 로그인 검증**: 각 역할 계정으로 **실제 로그인 → 화면 이동(`page.goto()`)** 까지 수행해, 후보조회 표시 금액과 생성된 항목 금액을 대조합니다(단위 테스트·서버 액션 직접 호출만으로는 대체 불가). 계정·절차·대조값 상세는 비공개.
- **음성 대조**: 가드 대상 외 역할·비소유 org 오더는 금액 조회가 거부되고 빈 목록으로 위장되지 않음을 확인합니다.
- **되돌리기 실측**: 권고안 C를 이전 정의로 되돌렸을 때 새 단언이 실패하는지 확인하고, 재적용 시 통과하는지 왕복 검증합니다(구현 PR에서 수행).

## 5. 스냅샷 갱신 주체 정리 (쓰기 경로)

### 5-1. 목표 판정 표 — 한 함수 `canWriteOrderRateSnapshot`로 단일화

| 역할 | 목표 판정 | 근거 |
|:--|:--|:--|
| `ADMIN` · `ZENITH_SUPER_ADMIN` | 허용 (현행 유지) | 기존 전체 권한 |
| `MANAGER` | **허용** (소유 여부 무관) | Aiden·Edward 확정: 입고 실측은 MANAGER도 수행하며 저장 시 재계산해야 함 |
| `OPERATOR` | **허용** (소유 여부 무관) | 동일 확정 |
| `AGENCY` | 소속 오더만 허용 (현행 유지) | 기존 소유 기반 판정 유지 |
| 그 외 비소유 역할 | 거부 → 갱신 생략 + warn | 음성 대조 기준 (Aiden 요청) |

- 허용 판단은 **`canWriteOrderRateSnapshot` 한 함수**에 모읍니다. 시스템 상수(`USER_ROLES`)를 사용하고 `role === 'MANAGER'` 같은 리터럴 비교를 새로 추가하지 않습니다.
- 현재 이 함수를 호출하는 쓰기 경로는 3곳(오더 생성 시 스냅샷 저장, 입고 실측 저장, 오더 수정 후 갱신)이며, 세 경로 모두 추가 역할을 자동으로 반영합니다. 다른 경로의 별도 판단 함수는 신설하지 않습니다.
