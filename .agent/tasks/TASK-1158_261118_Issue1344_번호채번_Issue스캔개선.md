## 1. 구현 내역 및 R-06 공식 문서 대조

1. **Issue 제목 조회 추가 (`scripts/next-task-number.sh`, `scripts/next-def-number.sh`)**:
   - 두 스크립트 모두 기존 로컬 파일 스캔(`.agent/ACTIVE_TASK.md`, `.agent/tasks/TASK-*.md`, `.agent/defects/DEF-*.md`, `.agent/VIOLATION_TRACKER.md`, `supabase/migrations/*.sql`)을 유지하면서 `gh issue list --state all --limit 2000 --json title` 결과를 합집합으로 스캔해 최댓값 + 1을 반환한다.
   - **패턴 격리 및 보수적 매칭**: `PREFIX=A`일 때 `TASK-[0-9]+` / `DEF-[0-9]+`는 `TASK-B-*`·`TASK-C-*`·`DEF-B-*`와 섞이지 않는다. 제목에 선행 참조 번호(예: `DEF-146 후속`)가 포함된 경우 최댓값이 올라갈 수 있으나 번호 충돌 방지를 위해 보수적(큰 번호) 방향을 허용하며, 이를 스크립트 헤더 주석(소유 주석·사용법·한계 포함)에 명시했다.
   - **출력 형식 현행 유지**: `TASK-%d`, `TASK-B-%d`, `DEF-%d`, `DEF-B-%03d`.
2. **폴백 동작**:
   - `gh` 미설치 또는 `gh issue list` 실패(미인증·네트워크 오류 등) 시 `stderr`에 `"⚠ 경고: Issue 미조회 — 번호 중복 가능, 수동 확인 필요 (...)"`를 출력하고 로컬 파일 기준 결과를 반환하며 `exit 0`으로 종료한다.
3. **R-06 공식 문서 / CLI 동작 대조 (Context7 및 `gh issue list --help` 실측)**:
   - 본 환경의 `gh` CLI는 GitHub 공식 CLI(`gh issue list --help`)로 동작하므로, `gh issue list --help` 출력 및 실제 저장소 대상 `gh issue list --state all --limit 2000 --json title` 실행으로 직접 대조했다(Context7에는 `cli/cli`용 정적 문서 대신 로컬 설치된 `gh` 바이너리의 내장 `--help`가 정확한 실행 버전 명세이므로 이를 근거로 사용).
   - `--help` 확인 결과: `-s, --state string {open|closed|all}`, `-L, --limit int (default 30)`, `--json fields (title 지원)`. 실제 실행 시 `--limit 2000`으로 저장소 전체 **482건**(`TASK-1165` 포함)이 페이지네이션되어 누락 없이 반환됨을 확인했다.
