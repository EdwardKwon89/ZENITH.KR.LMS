## 1. 시연용 오더 구성안 (건수·종류)
- **UPS 오더 3건**으로 최소 구성합니다. 전용 시연 화주·대리점 조직·계정을 사용하고 실제 고객 화면·통계와 분리합니다.
- 오더 식별 규칙: `remarks`에 **`DEMO-` 접두**를 붙입니다.

| 케이스 | 소유 구조 | 오더 수 | 목적 |
|:--|:--|:-:|:--|
| 부가운임 있음 | 대리점 소속 화주 | 1 | 부가항목·2 tier·3경로 |
| 조정 음수 | 화주 직접 | 1 | 음수 조정·직접 tier |
| 부가운임 0원 | 대리점 소속 화주 | 1 | 0원 케이스 |

### tier·경로 커버리지
| tier / 경로 | 관리자 | 대리점 | 화주 |
|:--|:-:|:-:|:-:|
| `ADMIN_TO_AGENCY` | O | O(청구받음) | — |

| `ADMIN_TO_SHIPPER`(화주 직접) | O | — | O(청구받음) |

- 청구서 상세 3경로(`finance`·`agency`·`shipper`)와 3 tier를 각각 1회 이상 포함합니다.
- 월 차수 청구서 3건으로 묶어 케이스별 행을 유지합니다(부가운임 오더 2건 + 0원 오더 1건 / 조정 음수 오더 1건).

## 4. 시연 시나리오 단계표

| # | 역할 | 화면 | 입력 | 기대 결과 유형 |
|:-:|:--|:--|:--|:--|
| 1 | 화주 | 주문 등록 | 오더 기본·화물·수하인 | 오더 생성 |
| 2 | 관리자 | 오더 목록 → 상태 변경 모달 | 배송완료 선택·사유 | 상태 전이 |
| 3 | 관리자 | 오더정산 상세 | 실측·원가 입력 | 정산 run 생성 |
| 4 | 관리자·대리점 | 청구서 생성 | 대상·기간·오더 선택 | 청구서 발행 |
| 5 | 관리자·대리점·화주 | 청구서 상세 3경로 | — | 금액·조정·부가항목 표시 |

- 공개 기재는 **단계 5개·역할 3종**만 씁니다.

## 5. 화면 경로·외부 호출 확인
- **단계 1~5 화면 리허설**: 실제 화면 **2/5 통과**(2단계 배송완료 전환, 5단계 청구서 상세 3경로), **1/5 실패**(3단계 정산 마감), **2/5 미실행**.
  - 1단계(화주 주문 등록 화면): 미실행(사유: fixture는 DB 직접 생성, 화면 입력 자동화 미완)
  - 3단계(오더정산 상세): **1/1 실패** — 화면 진입·입력 후 정산 완료 실행 시도, DB 상태 불변(run 0). 원인 미확인
  - 4단계(청구서 생성 화면): 미실행(사유: 3단계 선행 필요)
- **배송완료 전환 시작 상태**: `REGISTERED`(입력: 상태 선택·사유) → `DELIVERED` **1/1 통과**(관리자 실제 화면, DB 결과 확인).
- **3단계 실측·원가 입력 항목**: 실측 청구중량·가로/세로/높이, 기본운임·유류할증·긴급할증·기타항목. 입력이 하나도 없으면 화면이 `inputRequired`로 막아 정산 run이 생성되지 않습니다(코드·화면 확인).
- **오더 생성**: 화면 미실행 — B-407 fixture는 **DB 직접 생성**이었습니다. 시연에서는 화주 주문 등록 화면을 사용합니다.
- **정산마감·청구서 생성**: 서버 액션/DB fixture로 확인, 화면 클릭 경로는 미실행입니다.
- **외부 API 호출(코드 경로 기준)**: UPS·SHXK 호출이 필요한 단계 **2개**(창고 UPS 등록·UPS 라벨 발급) 확인. 해당 단계는 **실행하지 않음(미실행 사유: 외부 운송·비용 발생)**.
- **창고 입고 단계**: 외부 연동 호출 **0건, 아니오**(코드 경로 기준). 입고 자체는 외부 운송·비용을 일으키지 않습니다.
- **상태 변경 알림 메일**: 배송완료 전환 시 수신자 메일 발송 코드 경로 **1개** 확인. 시연 계정은 외부 고객 주소를 쓰지 않습니다.
