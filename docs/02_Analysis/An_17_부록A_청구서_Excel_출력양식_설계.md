# An_17 부록 A — 청구서 Excel 출력 양식 설계 (초안)

> **상태:** **v1.1 확정 (2026-11-21, JSJung 승인)** — 결정 7건 전부 확정(§9)

> **상위 문서:** `An_17_청구서관리_오더정산_청구서_설계.md` §5-2·§6-5(Excel 저장), Q10(VAT 별도)
> **독자:** 구현 Agent(Mike)가 이 문서만으로 셀 배치·인쇄 설정·테스트 단언을 만들 수 있어야 한다.

## 1. 원칙

1. **청구서는 "금액 스냅샷"의 출력물이다.** 금액·중량은 `zen_billing_statement_items`·`zen_billing_statements`의 저장값만 쓴다. 재계산하지 않는다. 출력 직전 `항목 line_total 합 = 헤더 total_amount`를 검증하고, 불일치하면 파일을 만들지 않고 실패(`logger.error`)한다.
2. **원가·마진·`platform` 판매가 등 다른 tier의 금액은 어떤 셀·숨김 열·메타데이터에도 넣지 않는다.** 대리점이 화주에게 보내는 파일에 Admin 원가 정보가 섞이면 안 된다(DEF-153과 같은 유형의 노출).
3. **VAT는 이 문서에 포함하지 않는다**(설계서 Q10 — 세금계산서 흐름과 연계, 별도 Task). 합계는 **"공급가액 합계"** 로 표기하고 "부가가치세 별도"를 명기한다.
4. **사용자 입력 문자열**(청구 대상명·수기 화주명 등)은 **문자열 셀로만** 쓴다. `=`·`+`·`-`·`@`로 시작해도 수식으로 해석되지 않게 한다(수식 주입 방지).
5. **읽기 전용 경로**(청구받은 화주, Admin 감독)도 같은 양식을 받는다(설계서 §6-5 확정). 접근 권한은 `getBillingStatementDetail`과 동일한 RLS로 판정하고, 보이지 않는 청구서는 미존재와 동일하게 응답한다.

## 2. 파일 구성

- 형식: `.xlsx`, **시트 2개** — ① `청구서` (요약, 1페이지) ② `오더별 상세`
- 파일명: `청구서_<statement_no>_<청구대상명>.xlsx` — 파일명 금지 문자(`\ / : * ? " < > |`)·공백은 `_`로 치환, 길이 80자 제한, `Content-Disposition`은 RFC 5987(`filename*=UTF-8''…`)
- 출력 경로: Route Handler `/api/finance/statements/[id]/export` (설계 확정). 서버 액션으로는 파일을 반환하지 않는다.
- 언어: v1은 **한국어 고정**(§8-3 결정 대상). 라벨은 상수 한 곳에 모아 두어 후속 다국어화가 쉽게 한다.

## 3. 시트 ① `청구서` (요약)

A4 세로, 열 6개(A~F), 열 너비 합계 약 95자. 아래는 배치 개념도이며, 셀 병합은 제목·블록 헤더에만 쓴다.

## 4. 시트 ② `오더별 상세`

열 14개(ADMIN_TO_AGENCY 청구서는 화주명 열 1개 추가, 총 15개). B-402부터 부가운임 항목·부가운임·운임 조정분 3열 추가(합계 앞). **수하인·도착국가 열 포함**(JSJung 결정). 열이 많아 세로 A4에서는 배율이 약 60%까지 내려가므로 **이 시트는 A4 가로**로 한다(§5, §9-7 확정).

| # | 열 | 값의 출처 | 형식 | 너비(자) | 정렬 |
|:-:|:--|:--|:--|:-:|:--|
| A | No | 1부터 순번 | 정수 | 5 | 가운데 |
| B | 오더번호 | `zen_orders.order_no` | 텍스트 | 17 | 왼쪽 |
| C | 운송장번호 | `zen_ups_labels.tracking_number` (`is_voided=false`, 다중이면 쉼표로 연결) | 텍스트(`1Z…` 보존) | 22 | 왼쪽 |
| D | 기준일 | 청구서 생성 시 기준(배송완료 또는 출고확정일) — `order_status_history` | `yyyy-mm-dd` | 12 | 가운데 |
| E | (ADMIN_TO_AGENCY만) 화주명 | 오더의 화주 조직명 또는 수기 `shipper_name` | 텍스트 | 16 | 왼쪽 |
| F | 수하인 | `zen_orders.recipient_name` | 텍스트(말줄임 없음, 셀 너비 초과 시 줄바꿈) | 16 | 왼쪽 |
| G | 도착국가 | `zen_orders.recipient_country_code` (ISO 2자리, 예: `US`) | 텍스트 | 9 | 가운데 |
| H | 청구중량(kg) | `charge_weight_kg` | `#,##0.00` | 11 | 오른쪽 |
| I | 기본운임 | `base_freight` | `#,##0.00` | 14 | 오른쪽 |
| J | 유류할증료 | `fuel_surcharge` | `#,##0.00` | 14 | 오른쪽 |
| K | 할증료 | `surge_fee` | `#,##0.00` | 14 | 오른쪽 |
| L | 기타 | `other_charges` | `#,##0.00` | 14 | 오른쪽 |
| M | 합계 | `line_total` | `#,##0.00` | 15 | 오른쪽, 굵게 |

(화주명 열이 없는 청구서는 E열이 빠지고 이후 열이 한 칸씩 앞으로 당겨진다. 구현은 열 정의 배열로 만들어 열 문자를 하드코딩하지 않는다.)

- **개인정보 최소화**: 수하인은 **이름만** 출력한다. 수하인 전화번호·주소·우편번호는 넣지 않는다(청구서 전달 대상이 화주·대리점이며 과세·정산에 불필요).
- 도착국가는 코드만 쓴다(국가명 번역은 후속). 값이 없으면 빈 칸.
- 수하인·도착국가·운송장은 **표시용 설명 열**이며 금액 스냅샷이 아니다. 출력 시점의 `zen_orders` 값을 쓴다.

- **행 구성**: 1행 제목(`청구서 번호 + 오더별 상세`), 2행 비움, **3행 열 머리글(회색 배경·굵게·테두리)**, 4행부터 오더 행(`order_no` 오름차순), 마지막 행 **합계 행**(굵게·상단 테두리, 중량·금액 6개 열 합 — 부가운임 포함, 운임 조정분은 0원이면 빈 칸).
- 합계 행 값은 DB 저장값의 합(수식 아님). 사용자가 Excel에서 합계 수식을 쓸 수 있도록 오더 행은 숫자 셀(문자열 아님)로 쓴다.
- 오더가 많으면(수백 건) 여러 페이지로 이어진다 — 열 머리글(3행)이 매 페이지 반복된다.

## 6. 서식 규칙

- 글꼴: `맑은 고딕` 10pt(본문), 제목 18pt, 합계 14pt. 머리글 배경 `#E7ECF3`, 합계 행 배경 `#F5F7FA`.
- 금액 열: 오른쪽 정렬, 음수는 괄호가 아니라 `-`로 표시(`#,##0.00;-#,##0.00`). **음수 금액은 현재 생성 경로에 없으나** 후속 조정 청구서 대비.
- 날짜: 문자열이 아니라 **날짜 값 + 표시 형식 `yyyy-mm-dd`**.
- 0 금액은 `0.00`으로 표시(공란으로 두지 않는다 — 조건 4b 0 금액 경고 건을 발행자가 볼 수 있어야 함).
- DRAFT: 시트 ① 제목 아래에 빨간 글씨 `초안 — 발행 전 문서`, 시트 ② 머리글에도 `[초안]` 접두. 발행 후 파일에서는 표시하지 않는다.

## 7. 오류·보안 동작

| 상황 | 동작 |
|:--|:--|
| 미존재·RLS로 안 보임 | 404 + 동일 응답(존재 비노출) |
| 항목 조회 오류·합계 불일치 | 500, `logger.error`, 파일 미생성(부분 파일 금지) |
| 항목 0건 DRAFT | 허용(빈 상세 + 합계 0) — 단 안내 행 `항목 없음` |
| 문자열 `= + - @` 시작 | 문자열 셀로만 기록(수식 아님) 테스트 포함 |
| 응답 헤더 | `Content-Type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`, `Cache-Control: no-store` |
| 로깅 | 성공 시 `logger.info`(statement_id·건수만, 금액·상호 제외) |

## 8. 테스트 단언 (구현 Task DoD)

1. **인쇄 설정 구조 단언**: 생성 파일을 다시 열어(파싱) 두 시트의 `paperSize=9`, `orientation=portrait`, `fitToWidth=1`, `fitToHeight`(요약 1 / 상세 0), 여백, `Print_Titles`(상세 3행), `Print_Area`, 머리글·바닥글 문자열이 **실제로 설정**되어 있음을 단언(소스 문자열 검사 금지).
2. **값 단언**: 시트 ② 오더 행 수 = 항목 수, 합계 행 = `total_amount`, 4개 금액 열 합 = 요약의 4개 금액(부가운임·조정은 별도 행·별도 단언), 오더 행은 숫자 셀.
3. **권한 단언**: 발행자·청구받은 화주(ISSUED/CLOSED)·Admin 감독 → 성공 / 타 대리점·DRAFT 청구받은 화주 → 404 동일 응답. 실제 authenticated 세션으로 검증(service_role 금지).
4. **주입 단언**: 청구 대상명 `=HYPERLINK(...)` → 셀 타입이 문자열.
5. **tier별 구성**: ADMIN_TO_AGENCY는 화주명 열 있음, 나머지는 없음.
6. **합계 불일치 단언**: 항목을 DB에서 조작해(테스트 fixture) 합계 ≠ 헤더일 때 파일이 생성되지 않음.
7. 구현을 되돌리면(예: 인쇄 설정 제거) 위 1번이 FAIL함을 확인해 PR에 기재.

### 9-7. 상세 시트 용지 방향 (확정)

- 기존 설계서(An_17 §5-2·§6-5)·WBS 4.6·이슈 #1366 DoD의 "A4 세로"는 **시트1(요약)에만 적용**하고, **시트2(오더별 상세)는 A4 가로**로 정정했다(2026-11-21). 수하인·도착국가 열 추가로 열 너비 합계가 약 150자가 되어, 세로면 배율이 약 60~65%(글자 5~6pt)로 떨어지기 때문이다. 가로는 약 85~90%(글자 약 8pt).
- 구조 단언(§8-1): 시트1 `orientation=portrait` / 시트2 `orientation=landscape`, 두 시트 모두 `paperSize=9`.
