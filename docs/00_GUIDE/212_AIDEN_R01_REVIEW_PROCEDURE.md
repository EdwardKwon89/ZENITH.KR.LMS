## 0. 성격과 범위

- 이 문서는 **Aiden의 검토 절차**를 정한다. 구현 Agent의 작업 절차는 GOV_COMMON.md R-17을 따른다.
- 검토 보조 도구(분류 힌트·Riley 호출·Shadow 원장)는 **저장소에 포함되지 않는 로컬 도구**이며, 결과는 공개 저장소에 쓰지 않는다(R-21).
- 검토 코멘트는 **목표 상태·판정 기준·해소 여부**만 쓴다. 현재 가드·권한 결과와 재현은 쓰지 않는다(R-21 §2).

## 1. 위험 등급

### 1-1. 원칙
1. 등급은 **PR 단위**이며 해당 항목 중 **가장 높은 등급을 승계**한다.
2. 변경 규모(파일 수·줄 수)는 등급을 낮추는 근거로 쓰지 않는다.
3. 판단이 애매하면 **한 단계 위**로 올린다.
4. Aiden이 **Riley 호출 전에** 판정하고, R-01 코멘트 **첫 줄**에 `위험 등급: 고(H2·H3)`처럼 근거 항목과 함께 쓴다. 이후 바꾸면 사유를 적는다.

### 1-2. 정의
| 등급 | 조건 |
|:-:|:--|
| **고** | H1 금액·정산·요금·환율·청구 / H2 인증·권한·RLS·관리자 기능 / H3 DB 스키마·RPC·마이그레이션·백필·삭제·롤백 / H4 외부 연동 payload·호출 / H5 운영·배포·되돌리기 어려운 작업과 이를 규정하는 문서 / H6 H1~H5 도메인 설계 PR. 보조: 가드·RLS·정산을 검증하는 테스트 PR은 대상 등급을 승계 |
| **중** | 위에 해당하지 않는 코드 변경(서버 액션·UI·공용 로직·i18n·일반 테스트·의존성) |
| **저** | 코드·마이그레이션·설정 변경이 없는 순수 문서(명세 정합, 인덱스, task file 수치·인용, WBS, IMP·DEF 등록)이며 H5·H6에 해당하지 않음 |

### 1-3. R-21 별도 축
문서·테스트·코멘트가 현재 정책·가드·운영 값·계정·로컬 경로를 다루면 등급과 무관하게 **R-21 전용 점검**(추가 줄 grep + 내용 확인)을 한다. 저위험 문서도 면제되지 않는다.

### 1-4. 예외
- **하향**: 고 → 중만 허용(저 불가). H 경로이지만 동작 무변경이 증명된 경우(로그 추가만, 주석, 오탈자)에 한하며, diff 전수 확인 근거를 코멘트에 쓴다.
- **상향**: 해당 영역에 DEF 이력이 있거나 R-21 위험이 겹치면 한 단계 위.

## 2. 검토 절차 요약
1. diff·코드·테스트·task file을 **전문** 읽는다. 문서 서술은 코드·테스트 본문으로 확인한 뒤에만 인용한다.
2. 코멘트에 쓸 주장마다 **파일·줄(또는 명령 결과) 근거 표**를 먼저 만든다. 근거 없는 주장·승인 의견은 쓰지 않는다(`미확인`).
3. 가드·거부·권한 로직은 호출처를 `git grep`으로 전수 추적해 우회 경로를 확인한다.
4. 테스트는 **무엇을 단언하는가** 표를 만들어 항상 참인 단언을 가려낸다.
5. 금액·RLS·DB 마이그레이션 PR은 게시 전에 결론을 **반대로 반박**해 본다.
6. CI는 게시 직전에 재조회한다. R-21 grep과 링크한 코멘트 ID 대조(작성자·번호)를 게시 전에 한다.
7. 결과는 `확인함 / 추정 / 미확인`을 구분해 쓴다. 승인 권고에는 CI 통과 조건을 명시하고, 병합은 하지 않는다(해당 팀 리더 소관).

## 3. Riley 활용과 독립 대조 선행 순서

### 3-1. 순서 (필수)
1. 등급 판정(§1).
2. **Aiden 독립 대조를 먼저 끝낸다.** 발견 목록과 **완료 시각**을 로컬 기록에 남긴다.
3. 그 뒤에 Riley를 호출하고, **그 전에는 Riley 출력을 열지 않는다**.
4. Riley의 각 지적을 코드로 확인해 `맞음 / 일부 맞음 / 틀림`으로 라벨하고, Aiden이 낸 심각도로 재판정한다(Riley는 과대 경향).
5. **Riley 미탐**(Aiden 독립 대조에서 찾았으나 Riley가 놓친 필수 결함)을 PR별로 기록한다. 없으면 `없음`으로 기록한다.

### 3-2. 이유
이중 검증의 핵심 위험은 "Riley가 놓친 결함을 Aiden도 안 보게 되는 것"이며 게이트가 재는 오탐률로는 측정되지 않는다. 독립 대조가 Riley 출력보다 **먼저** 있어야 미탐을 신뢰할 수 있게 셀 수 있다. 이 순서 때문에 **시간 절감은 이중 검증 축소(§4)가 적용된 뒤에만 생긴다.**

### 3-3. 모델
고 = XHigh, 중·저 = Medium(필요 시 XHigh). Riley의 입력은 저장소의 공개 내용뿐이며 출력은 로컬에만 두고 그대로 게시하지 않는다.

## 4. 이중 검증 축소 단계

### 4-1. 단계
| 단계 | 대상 | Aiden이 하는 일 | 진입 조건 |
|:-:|:--|:--|:--|
| 0 (현재) | 전체 | 모든 지적을 코드로 확인 + 독립 대조 | — |
| 1 | 저위험 | `needs_check`와 감사 표본 20%만 코드 확인, `auto_pass`는 발췌 대조 | 라벨 60건 이상, 틀린 통과 7% 이하가 정식 점검 2회 연속, 저위험군 Riley 미탐 0건 |
| 2 | 중위험 | Riley 지적은 발췌 대조, "문제 없음" 중 가드·권한 관련만 샘플 재검증 | 1단계 유지 + 중위험군 미탐률 기준 확정 후 |
| 3 | 고위험 | **축소하지 않는다**(전수 + 반박 점검) | 해당 없음 |

### 4-2. 안전장치
1. 모든 단계에서 감사 표본 20%는 코드 확인을 유지한다.
2. Riley 출력의 필수·권고 심각도는 단계와 무관하게 Aiden이 재판정한다.
3. 축소한 PR의 R-01 코멘트에는 "Riley 결과 활용, 확인 범위"를 명시한다.
4. 고위험 PR, 설계 확정, `status:ready`, 병합 권고는 축소 대상이 아니다.

### 4-3. 자동 복귀 규칙
- 틀린 통과율이 **7%를 넘는 정식 점검이 2회 연속**이면 직전 단계로 복귀한다.
- 축소 단계 대상군에서 **Riley가 놓친 필수 결함이 1건이라도 확인되면 즉시** 직전 단계로 복귀하고 원인을 분석한다(연속 조건 없음).
- Riley 모델이나 통과 임계값(θ)이 바뀌면 해당 단계의 지표를 **다시 측정**한다.

### 4-4. 적용 시점
- 정식 점검은 **2주 또는 라벨 누적 30건 중 먼저 오는 쪽**으로 하며 첫 점검은 2026-12-04다.
- 12-04 점검은 **1단계 진입 가능 여부를 판정**하는 데까지만 쓴다. 실제 적용은 시연 이후 첫 저위험 PR에서 시범으로 시작한다(Edward 승인 2026-11-28).
